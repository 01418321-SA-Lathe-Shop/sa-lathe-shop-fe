# Phase 5 — Admin Worker Management

Status: **Implemented and verified as a local demo for review**, 2026-10-15. Real authentication/password changes remain deferred to Backend integration; this is not a production account system.

## Owner-confirmed scope

The owner approved the following before implementation:

- Admin may add/edit Workers and deactivate/reactivate them.
- Worker name, email, and phone are all required.
- Admin may change Worker passwords (superseding the earlier proposal to omit password management).

No permanent deletion, job assignment/reassignment, new Admin permissions, master-data management, or order approval was added. Existing Admin/Worker UC6 purchasing remains unchanged. Worker management has no numbered UC in the source; it is the confirmed Admin-management function alongside UC1–UC9.

## Implemented screen and data flow

Admin demo → Workers panel at existing `/` → contact/status/password form → pure local rule → shared browser-memory profiles → refreshed list/detail/notices.

| Feature | Local behavior |
|---|---|
| List/search/filter | Synthetic Worker profiles, active/inactive status, search by name/email/phone, all/active/inactive filters, no-match state with Clear filters |
| Add | Required name/email/phone; UUID generated by browser; synthetic new profiles default active; no credential created |
| Edit | Update contacts while preserving UUID, status, and password-change simulation metadata |
| Deactivate/reactivate | Confirmation required; profile remains present with inactive/active status; no records deleted |
| Password change | Open masked new-password/confirmation form, validate nonempty matching synthetic values, clear both values after attempted submission, display explicit simulated outcome and a timestamp |
| Cancel / Escape | No committed profile/status/password-simulation change; password form unmounts and dialogs return focus to their opener |
| Reset/reload | Restore all role fixtures; reset also remounts forms to discard pending edits/evidence; generic demo role may restore from sessionStorage |

Committed profile changes survive navigation and role switches through the existing shared provider. Unsubmitted forms do not persist after unmount. Profiles are not linked to the generic Worker demo login or manufacturing job ownership.

## Password/security boundary — essential

**No real password changes in this phase.** The existing login is a role selector, not an account authentication service. The form visibly says “Demo only” and its action is “Simulate password change.” Use made-up values only.

- Passwords are held only by masked form inputs while being entered. Submission compares the two values, resets the form immediately, and never places their text in a reducer action, shared state, fixture, browser storage, request, or app log.
- Cancel, Escape, or navigation unmounts the form. Reopening presents empty fields.
- Only `passwordChangeSimulatedAt` is added to the local profile, labeled as simulation metadata rather than a real credential-change audit field.
- No password/hash, custom hashing/authentication, credential endpoint, reset email, auth provider, secret, or dependency is introduced.
- Production authorization and identity/ownership checks, password-strength policy, Admin reauthentication, session revocation, notifications/audit, account provisioning, and inactive-login enforcement remain D01/D15. Backend must define and enforce them.
- Deactivation changes profile status only in this prototype. It cannot disable a generic role-selector login. Existing jobs, orders, stock, and invoice data are untouched.

Auth guidance informed this boundary; it was not used to select or install a new provider or replace the agreed Go Backend stack.

## Run and try

```text
npm run dev
```

Open the URL printed by Next.js → choose Admin demo → Workers. Two synthetic profiles are supplied: one active and one inactive. Add a Worker with all three contacts; edit it, deactivate/reactivate, and try the password-change simulation. Switch to Material orders and back or sign out/re-enter Admin: committed profiles persist until reload or global reset.

The checked production preview used `http://127.0.0.1:3101`. No public deployment was performed.
